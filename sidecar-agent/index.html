What does a sidecar agent observe?

A sidecar agent sits alongside a workflow and observes signals made available to it. What it can notice depends on the inputs and rules it has actually been given; a separate handoff carries the relevant context to the next reviewer.

Useful signals

A sidecar might compare an agreed file boundary with a proposed file change, a requested check with a reported result, or a stop condition with an event. It can surface a mismatch for review. It cannot infer intent or prove an unseen action happened merely because a report says so.

Walk through a scope warning

In this invented example, the agreement permits edits to a signup form. The agent proposes changes to the form and to account policy. A sidecar that receives both the agreement and the proposed file list can flag the policy file as outside scope. It presents the relevant boundary and file to the person.

The person may narrow the patch, explicitly expand the task, or reject it. If the sidecar never receives the file list, it cannot make that comparison; absence of a warning is not proof that the work stayed within scope.

Observation needs a next action

A good warning includes the signal, the rule it may conflict with, the evidence available and who can decide. It should distinguish a proposal from an action already taken.
