01 / Harness Map

Harness Map

Das Harness ist keine App-Schale. Es ist die Entscheidungskette.

Jeder Block hat eine andere Aufgabe. Wenn ein Block fehlt, sieht Agentenarbeit produktiv aus, aber der Mensch verliert Kontrolle.

  1. 01
    Owner PacketHuman Ownership — Ziel, Risiko, Human-only. Der Mensch setzt Ziel, Risiko und Abbruchlinie. Agenten arbeiten erst sinnvoll, wenn Ziel, Nicht-Ziel und Human-only Entscheidungen sichtbar sind.
  2. 02
    Scope Boundarykleiner Auftrag statt Rohwunsch. Der Auftrag wird klein genug, dass Erfolg pruefbar ist. Das Harness trennt Wunsch, Kontext, Nicht-Ziel und erlaubte Aktionen, bevor der Agent arbeitet.
  3. 03
    Delegation Carderlaubt, verboten, Artefakt. Das Tool bekommt Rolle, Grenze und Artefaktpflicht. Die Delegation Card ersetzt den diffusen Prompt durch Ziel, Scope, Human Gates und Verifikation.
  4. 04
    Verifier LoopBelege statt Done-Text. Done ist erst wahr, wenn Belege danebenliegen. Tests, Diffs, Dateien, Screenshots oder Reports schlagen die Erfolgserzaehlung des Agenten.
  5. 05
    Next Actionanschlussfaehige Entscheidung. Am Ende steht eine Entscheidung, kein Rohlog. Der Mensch sieht, was geaendert wurde, welche Belege existieren, was offen bleibt und was als naechstes passiert.

Wenn ein Block fehlt, sieht Agentenarbeit produktiv aus, aber der Mensch verliert Kontrolle.

04 / Human Gates

Human Gate Simulator

Der Agent darf nicht jede Unsicherheit in Aktion umwandeln.

Markiere, was in deiner Aufgabe vorkommt. Das Gate entscheidet, ob das Tool laufen darf oder erst eine menschliche Freigabe braucht.

  • neue Dependency
  • destruktive Aktion
  • Secrets, Auth oder Deploy
  • Scope wird groesser
  • unklare Tests oder unbekannter Fehler
  1. 01
    RUN: Das Tool darf bounded arbeiten.Kein harter Human Gate aktiv. Der Auftrag braucht trotzdem Artefaktpflicht und Verifikation.
  2. 02
    WARN: Der Agent darf nur diagnostizieren.Unklare Tests oder unbekannte Fehler brauchen erst Reproduktion und Beleg, nicht direkt einen Fix.
  3. 03
    STOP: Erst Human Gate, dann Codex.Mindestens ein harter Gate-Faktor ist aktiv. Der Mensch entscheidet Scope, Risiko oder Freigabe, bevor der Agent weiterarbeitet.

WARN. Unklare Tests oder unbekannte Fehler brauchen erst Reproduktion und Beleg, nicht direkt einen Fix.

05 / Runbook

Runbook

Eine Agenten-Session laeuft in sechs kontrollierten Bewegungen.

Oeffne die Schritte. Jeder Schritt ist ein eigener Gate-Punkt.

  1. 01
    Intakelesen, nicht bauen — Das Tool liest Kontext, HAI-Ziel und Auftrag. Output: Was ist klar, was ist unklar, welche Artefakte waeren sinnvoll?
  2. 02
    Planmaximal sechs Schritte — Der Plan nennt Artefakt, Beleg und Human Gate pro Schritt. Noch keine Datei-Aenderung.
  3. 03
    Bounded Buildnur der vereinbarte Scope — Der Agent arbeitet klein. Wenn der Ansatz kippt oder breiter wird, stoppt der Lauf.
  4. 04
    EvidenceTests, Diffs, Dateien — Erfolg wird als Beleg sichtbar: Checks, Smoke-Test, Doku-Struktur, Screenshot oder Diff.
  5. 05
    Reviewkritische Gegenpruefung — Der Agent sucht Scope Drift, falsche Claims, fehlende Belege und riskante Empfehlungen.
  6. 06
    Handoffnaechste Entscheidung — Der Mensch bekommt keine Rohgeschichte, sondern: geaendert, Belege, offen, naechste Entscheidung.

Handoff. Der Mensch bekommt keine Rohgeschichte, sondern: geaendert, Belege, offen, naechste Entscheidung.
