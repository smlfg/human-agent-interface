Lessons Learned
Lesson 1
Iron Rule: Fail-Open
Sidecar darf Claude nie zum Absturz bringen. Jede Exception wird gefangen, schlimmstenfalls gibt der Daemon {} zurueck. Das Tool das ueberwacht darf nie das ueberwachte Tool blockieren.
Lesson 2
Self-Detection ist Pflicht
Ohne SELF_MARKERS-Check erkennt Sidecar seine eigenen [SIDECAR]-Warnungen als neue Events → Endlos-Loop. Jedes Monitoring-System muss sich selbst ausschliessen.
Lesson 3
Sync-Hooks muessen schnell sein
Claude Hooks blockieren den Workflow. Unix Socket + asyncio halten die Latenz bei ~1-3ms. Timeout-Safety auf jeder Schicht: Bridge 10s, Hook 15s, LLM 8s.
Lesson 4
Cooldown verhindert Spam
Ohne Cooldown (15s) wuerde jeder Call eine Warnung produzieren. Claude bekommt sonst mehr Meta-Kontext als Nutz-Kontext. Weniger ist mehr bei Context Injection.
Lesson 5
Intelligent filtern statt alles laden
v1 → v2 war der groesste Paradigmenwechsel: Statt 900 Zeilen permanent zu laden, waehlt ContextSelector ~20 phasenrelevante Zeilen. CLAUDE.md schrumpfte um 45%.
Lesson 6
File Locking ist nicht optional
Mehrere Hooks feuern parallel (PostToolUse + PreToolUse). Ohne fcntl-Lock korrupte JSON Session-Dateien. Race Conditions sind real bei Event-driven Architekturen.
Lesson 7
Budget-Caps vor Feature-Creep
Der LLM Judge koennte bei jedem Call evaluieren — tut er nicht. $0.05/Tag Cap + Dedup Cache + 3 gezielte Trigger halten die Kosten negligible. Constraints erzwingen gutes Design.
Lesson 8
Phase Tracking ist bilingual
Samuel schreibt Deutsch, Code-Prompts sind oft Englisch. PhaseTracker braucht Keywords in beiden Sprachen. Internationalisierung ist kein Nice-to-have wenn der User zweisprachig arbeitet.
Alles an einem Tag. Die gesamte Evolution von v1 bis v3 passierte am 4.–5. Maerz 2026. 15 Commits, 5.630 Zeilen Code, von einem asyncio Daemon mit Pattern Detection zu einem dreischichtigen QA-System mit LLM Judge. Publiziert auf GitHub: smlfg/sidecar-v1, smlfg/sidecar-v2, smlfg/sidecar-v3.
