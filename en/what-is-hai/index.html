What is HAI?

HAI stands for Human Agent Interface. It is the control layer between people and autonomous AI agents: it keeps agentic work observable, bounded, verifiable, and human-owned.

The definition See the proof
Checked · Human
01 / Definition

Definition

A control layer, not a chat window.

Human Agent Interface (HAI) is an open-source control layer for keeping agentic AI work observable, bounded, verifiable, and human-owned.1

HAI does not answer how an agent is built. It answers who owns the task, what the agent may do, when it must stop, and which evidence supports a result. The four properties hold together.

  1. 01
    ObservableYou see what the agent does, with which tools, and why.
  2. 02
    BoundedEvery task has scope, permissions, and stop rules. Work outside the contract does not run.
  3. 03
    VerifiableResults need evidence: sources, diffs, test results. Plausibility is not proof.
  4. 04
    Human-ownedA named person reviews and decides. Responsibility is not delegated to the system.

Canonical. The four properties are conditions, not product features. If one is missing, the work is not human-owned.

02 / Problem

Why HAI is needed

The problem is loss of control.

Once several agents plan, execute, delegate, or prepare results, questions stay open: Who owns the task? What may the agent do? Which limits apply?

What evidence exists? When must it stop? Who reviews and decides?

Without a control layer, agentic work becomes invisible, hard to verify, and organizationally unaccountable. The problem is not the speed of agents. It is the gap between execution and responsibility.2

Without HAI. The work is fast. The responsibility is invisible.

03 / Sequence

How it works

Five steps, one decision.

HAI describes a sequence that starts before execution and does not end after it. The steps are ordered; a later step does not replace an earlier one.

  1. 01
    IntentA person states the task and its purpose. The agent may sharpen the wording but does not set the goal.
  2. 02
    ContractScope, permissions, stop rules, and completion criteria are fixed before execution. The contract is the boundary the agent works within.
  3. 03
    ExecutionThe agent works inside the contract. Every tool call stays attributable to a task and an owner.
  4. 04
    EvidenceThe result arrives with proof: sources, changes, checks, open points. A summary is not evidence.
  5. 05
    DecisionA named person accepts, rejects, or narrows the result. The decision is recorded with date and reason.

Order. Intent and contract are not paperwork. They decide whether execution stays verifiable.

04 / Boundaries

What HAI is not

Four boundaries.

The boundary is part of the definition. Without it, HAI becomes a label for anything involving agents.

  1. 01
    Not a chat interfaceHAI is not a surface you type into. The control layer sits above execution, not in its place.
  2. 02
    Not prompt engineeringHAI does not optimize wording. It governs permissions, limits, evidence, and decisions.
  3. 03
    Not a finished enterprise platformHAI is an approach. HAI-MCP is an open-source implementation; this page claims no finished product.
  4. 04
    Not autonomy without limitsHAI is not a tool for increasing autonomy. It makes limits visible and records who may move them.

Boundary. HAI is not a chat interface and not a finished enterprise platform. HAI is an approach and a control layer for human-owned agentic work.

06 / FAQ

FAQ

Four questions.

01

Is HAI a product?

No. HAI is an approach and a control layer. HAI-MCP is an open-source implementation that exposes the approach through MCP.

02

Do you need HAI-MCP?

No. The control layer can be described independently of an implementation. HAI-MCP is one way to bring it into compatible agent and tool systems.

03

Who is HAI for?

For people and teams that use agentic work and need ownership, limits, evidence, and stop rules. Not for the question of how to build an agent.

04

How is HAI different from agent frameworks?

Frameworks answer how an agent is built and executed. HAI answers how that work stays observable, bounded, verifiable, and human-owned. HAI does not replace a framework; it sits above or beside it.3

Test question. If the answer is “more autonomy”, it is not HAI.
