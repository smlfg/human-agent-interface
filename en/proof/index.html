The Proof.

PenEcho, HAI-MCP and Plaud are three parts with one principle: the human sets the frame, the agent works inside it, the evidence decides. None is HAI on its own, none is finished. This page separates evidence, practice and gap.

02 / PenEcho

Pen and e-ink

The agent writes on the same page.

PenEcho is a bidirectional e-ink algebra tutor. You work with a pen on a reMarkable Paper Pro. The agent reads the page and writes back on it — no chat window, no device switch. It gives hints, not solutions.

The loop

The loop has four steps on one page. The page is the shared state.

  1. 01
    You write. Task and working as handwriting.
  2. 02
    The agent reads. You trigger it deliberately.
  3. 03
    It answers. Red or green, on the right step.
  4. 04
    You continue. On the same page.

Definition of Done, Level 1

L1 is met when all six points hold on the device — with no laptop input:

  1. 01
    Task. 3(x+2)=15 and the wrong step 3x+2=15 are on the page.
  2. 02
    Trigger. You trigger the agent; it does not write unasked.
  3. 03
    Hint. It recognises the error and writes a short pen hint on the same page.
  4. 04
    Writing. Your handwriting stays; nothing is overwritten or deleted.
  5. 05
    Three switches. Human → agent → human, on the same page.
  6. 06
    Latency. The first stroke time is measured and recorded in SETUP.md.

Point 6 is uncomfortable: without a measurement there is no latency number. That is why none is given here.

What is proven — and what is not.

A technical basic proof exists: extend the page file, transfer it back over SSH, restart the note UI. That is a permitted intermediate step, not L1. L1 requires a session without laptop input.

Not proven is seamless write-back: hints on the open page, without restart, close/reopen or device switch. That is a decided product requirement, not a demonstrated implementation. Colour is not proven either.

Product contract: github.com/smlfg/penecho. Implementation: github.com/smlfg/algebra-agent. The contract describes the target, not a running system.

03 / HAI-MCP

MCP

The control plane.

HAI-MCP is the open-source control plane for bounded agent work: a Python MCP server. The model stays in the client; the server never calls a model. It manages state, rights, contracts and evidence.

MCP is the channel. That makes it model-agnostic: any compatible client uses the same tools. The server is not an agent.

What the control plane holds

The control plane holds five things:

  1. 01
    Missions. Problem, artifact, time limit, done criteria.
  2. 02
    Contracts. The frame for the work.
  3. 03
    Leases. Time-bounded authority on one contract.
  4. 04
    Owner gates. Human approval before state changes.
  5. 05
    Audit. The trail of decisions.

23 tools — per the public Glama extraction, 8 Sep 2026. The number can change.1

The server does not approve work. It records what is allowed, what happened and what counts as evidence. The owner decides.

04 / Plaud

Voice

A recording is not a mission.

Plaud is the voice input: it records, then supplies transcripts and notes. In five months, 223 transcripts have accumulated — our own count.2

Plaud is capture, not a control plane. A recording does not create a mission. A session reads the files, decides, and creates zero to n intakes. Typically no more than three links per recording; unclear recordings stay at zero links.

No auto-intake, no auto-mission

The intake contract is n:n: a recording can feed several projects, a project many recordings as evidence. A mission is optional and late.

Rejected: the linear funnel, auto-intake, auto-mission. The contract is docs only, owner ack 19 Aug 2026 — no stable, no runtime, no qualify.3

n:n means allowed, not required. Unclear stays at zero.

05 / What is missing

Limits

What is missing.

A proof page that hides gaps is a sales page. Four gaps are open:

  1. 01
    No runtime connection. The three parts are documented separately. No connected run turns a recording into ink through the control plane.
  2. 02
    No external case study. No published account by another person or team using all three end-to-end.
  3. 03
    No independent audit. HAI-MCP is open source and readable. That is inspection, not third-party review.
  4. 04
    PenEcho L1 is not complete. The DoD items are open; a run with three handovers without laptop input is not demonstrated.

What changes is added with a date. What is missing stays listed as a gap.

No evidence without a date. No date without an owner.
