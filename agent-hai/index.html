One agent using HAI: request to review

A useful handoff lets someone reconstruct the path from a request to a decision. This illustrative signup-form example follows one agent through that path.

1. Agree on the work

The person asks: make an empty email field explain what is missing. The agent restates the goal: update the message for that field and check the empty and filled cases. It will not change account rules or publish the site.

2. Question and act

The agent notices that a broader email-policy change might also help. It raises the idea but keeps working within the agreed boundary. The person can accept that suggestion as a separate task, change the scope explicitly, or decline it. Saying an idea aloud does not by itself decide who adds it to the work.

3. Return evidence

The agent reports the changed form file, the new message and the outcomes of the empty and filled cases. If it could not run a check, it says so instead of presenting the result as verified.

4. Review and decide

The person reads the change, checks that the message addresses the request, and accepts it or asks for a correction. A suggestion to change account policy remains open until the person decides on that consequential scope change. The agent can still challenge the review if it sees a problem.

For the underlying distinction, see Is HAI an agent? and the HAI definition. For a reusable review packet, see the handoff checklist.
