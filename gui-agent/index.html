How a GUI agent works

A GUI agent works through a visible interface: it observes a screen, chooses an action and checks what changed. Each step can return control to a person.

A fictional task: save a draft

A person asks an agent to create a draft note titled “Team agenda” in a fictional notes app. The boundary is to save a draft only. The agent must stop before sharing or publishing it. The panels below are illustrations, not a recording or a live interface.

  1. 01 · Observe
    Notes / New note
    Title: empty
    Content: empty
    Save draft

    The agent sees an empty note editor and a Save draft control. It checks that the visible page matches the requested task.

  2. 02 · Act
    Notes / New note
    Title: Team agenda
    Content: empty
    Save draft

    The agent enters the requested title and selects Save draft. It does not select a share or publish action.

  3. 03 · Verify
    Notes / Drafts
    Team agenda — Draft
    Saved

    The agent observes the draft listed with its title and saved status. That visible result supports the claim that the draft was saved in this example.

  4. 04 · Stop
    Notes / Drafts
    Team agenda — Draft
    Next decision: share or keep private?

    The agent reports the observed result and stops. Sharing would require a separate human decision; if the saved status were missing, it would report uncertainty instead of claiming success.
