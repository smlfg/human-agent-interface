Eine Website-Änderung mit Claude Code nachvollziehen

Vier Kacheln auf der Startseite wurden bedienbar. Der Git-Verlauf zeigt die Änderung und ihre spätere Weiterentwicklung – und liefert damit etwas, das sich unabhängig von einer Abschlussmeldung prüfen lässt.

Der Ausgangspunkt und die Änderung

Im Commit e1ae5e6: vollständiger Vorher-Nachher-Diff steht Claude als Autor und Claude Opus 5.5 als Co-Autor im Git-Metadatensatz. Die zuvor statischen CLI-, TUI-, GUI- und HAI-Kacheln wurden zu Buttons. Jede öffnete eine passende Erklärung unter der Reihe; die HAI-Erklärung verlinkte auf die Definition weiter unten.

Die Buttons erhielten aria-expanded und aria-controls="epoch-detail". Beim Wechsel schließt das Skript den vorherigen Eintrag; ein erneuter Klick schließt das Detail. Der Commit ergänzt außerdem im Worker die erlaubten Tracking-Ziele epoch_cli, epoch_tui, epoch_gui und epoch_hai für cta_click. Der Diff zeigt sowohl Oberfläche als auch Allow-List.

Selbst am Verlauf prüfen

In einem lokalen Klon zeigen diese Befehle das Ausgangsbild und die Änderung; sie verändern keine Dateien:

git show e1ae5e6^:index.html
git show e1ae5e6 -- index.html src/worker.js
git show a2f98a3 -- index.html

Der Folgecommit a2f98a3 ersetzte das gemeinsame Detailfeld durch unabhängig umklappende Karten mit aria-pressed. Wer nur die aktuelle Seite betrachtet, sieht daher nicht zwangsläufig den Zustand von e1ae5e6.

Was wurde neu überprüft?

Für diesen Artikel wurde die HTML-Datei aus e1ae5e6 separat im Browser geladen: CLI öffnen, zu HAI wechseln und HAI schließen änderte die Sichtbarkeit und aria-expanded wie erwartet. Das ist eine spätere lokale Wiederholung, kein Nachweis eines historischen Tests. Der Commit belegt auch nicht, welche einzelnen Entscheidungen Samuel damals getroffen hat; eine private Sitzung wird hier nicht als Quelle verwendet.

Eine Meldung „fertig“ ist ein Hinweis. Erst ein sichtbarer Stand, ein Diff und eine überprüfbare Interaktion machen das Ergebnis nachvollziehbar.

Dieser Blick auf Eingabe und Arbeit des Agenten ist eine redaktionelle Leitlinie: Menschen sollen sehen können, was beauftragt und was tatsächlich verändert wurde.
