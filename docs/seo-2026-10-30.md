**Scope:** the eight rebuilt pages (`/`, `/en/`, `/was-ist-hai/`, `/en/what-is-hai/`, `/beweis/`, `/en/proof/`, `/mesh/`, `/en/mesh/`) and `sitemap.xml`.

**Canonical host:** `https://www.human-agent-interface.com/`. Live check on 2026-10-30: apex `https://human-agent-interface.com/` returns `301` to the `www` host; `www` returns `200`.

### 4.2 High — the two legal pages are `noindex` but listed in the sitemap

`/impressum/` and `/datenschutz/` both contain:

```html
<meta name="robots" content="noindex">
```

Neither has a canonical link. They are nevertheless included in `sitemap.xml` because the brief explicitly asked for the legal pages. This is a contradiction: Google generally ignores sitemap entries for URLs that return `noindex`, and Search Console will report them as “Excluded by noindex tag”.

Two consistent options:

1. **Index them** (recommended for legal pages): remove the `noindex` meta tag, add a self-referential canonical (`https://www.human-agent-interface.com/impressum/` and `/datenschutz/`), and keep them in the sitemap. This requires editing two files outside the eight-page write scope.
2. **Keep them `noindex`**: remove both entries from the sitemap. They remain reachable from every footer.

They are currently linked from all eight new pages, so they are not orphaned either way.

## 5. Legacy pages — recommendation and exact file contents

### 5.1 Recommended mechanism

Use **`_headers` with `X-Robots-Tag: noindex, follow`** as the primary mechanism, plus **three exact 301 redirects in `_redirects`** for the true duplicates. Do **not** delete the legacy directories yet.

Why this combination:

- **Keeps ad landing pages and old backlinks working.** `/proof/ads/*` and the interactive course pages are still linked from ads and old material. A 404/410 or a blanket redirect would break them.
- **Removes legacy pages from the index without deleting content.** `X-Robots-Tag` is honored by Google and Bing, and it is applied by Cloudflare to static asset responses.
- **Reversible.** Removing a block from `_headers` restores the previous state; nothing is lost.
- **Redirects win over headers.** Cloudflare evaluates `_redirects` before `_headers`, so the three exact duplicates return a 301 while the rest of the legacy tree returns `200` with `noindex, follow`.
- **Do not use `robots.txt Disallow` for these paths.** A disallowed URL cannot be fetched, so the crawler never sees the `noindex`; the URL can remain indexed as a bare link. `robots.txt` currently allows everything, which is what this plan needs.
- **Do not blanket-redirect the legacy tree to `/`.** Google treats irrelevant redirects to the home page as soft 404s and may ignore them. Only redirect where the new page is the same topic and the same language.
- **Removal is option C, not option A.** Once server logs and Search Console show no organic traffic or ad clicks to a legacy directory, delete it (or add it to `.assetsignore`). That is the cleanest end state but should not be the first move.

Deployment facts that make this work:

- `_headers` and `_redirects` are read from the static asset directory. Here that is the repository root (`assets.directory: "."`).
- `_headers` applies to static asset responses only. It does **not** apply to responses generated by `src/worker.js` (`/`, `/index.html`, `/intake`, `/api/*`). The legacy pages are static assets, so they are covered.
- Cloudflare allows up to 100 `_headers` rules and 2,000 characters per line. The proposed file uses far fewer.
- `_redirects` rules are evaluated before `_headers`.

Source: Cloudflare Workers static assets documentation, “Headers” (custom headers, `X-Robots-Tag`, redirect-before-headers, 100-rule limit).
